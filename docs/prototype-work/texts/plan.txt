## 서비스 개요
누구에게 무엇을 팔고, 어떻게 돈을 버는지 정리합니다.
식
식업
“사장님 매장 살림, 로고까지 한 번에”
이름의 뜻
식(食, 음식) + 업(業, 생업). 음식으로 생업을 꾸리는 외식업 사장님의 일을 뜻합니다. 그 장사에 필요한 소모품 구매·재구매와 매장 로고 맞춤 제작을 한곳에서 돕는다는 뜻을 담았습니다. 영문 표기는 sikup.
도메인 (2026-10-14 조회)
sikup.co.kr 비어 있음 — 이것부터 등록. sikup.com은 다른 사람이 보유 중(Sedo에서 판매)이라 필요해지면 구매 검토.
바로 할 일
도메인 sikup.co.kr 등록(국내 등록대행자), KIPRIS 상표 검색 후 출원(35·16·40·42·9류). 업종을 뜻하는 말이라 식별력은 변리사 확인 필요(법률 자문 질문서 P-01).
1차 타깃 · 핵심
#### 소상공인 외식업 사장님
개인 식당·카페·배달 전문점. 여러 품목을 소량씩 자주 사고, 가격에 민감하며, 발주 시간을 줄이고 싶어 합니다. 매장 로고가 들어간 수저집·컵 같은 맞춤 제작품 수요가 큽니다.
2차 타깃 · 객단가
#### 프랜차이즈 본사·가맹점
대량 구매, 브랜드 통일 디자인, 여러 매장 배송이 필요합니다. 본사 지정 품목·견적 기반 거래가 중심입니다.
3차 타깃 · 확장
#### 급식·케이터링·호텔
정기 대량 구매와 세금계산서 기반 결제가 중요합니다. 정기배송·후불결제와 잘 맞습니다.

## 사용자 앱/웹 주요 기능
B2B 소모품 구매의 특성(반복 구매, 수량별 단가, 세금계산서)과 맞춤 제작을 함께 담습니다. 기능 상세 명세 →
MVP 1차 출시2차 출시 후 3개월 안3차 확장핵심 차별 기능
#### 회원·인증
- MVP
SNS 간편가입·로그인
MVP는 카카오·애플, 네이버·구글은 2차(구글은 웹뷰 안 로그인을 막아 별도 처리 필요). iOS 앱에 다른 소셜 로그인을 넣으면 개인정보 보호 기능을 갖춘 동등한 로그인 옵션(애플 로그인 등)도 제공해야 합니다(앱스토어 가이드라인 4.8).
- MVP
이메일 가입·로그인
SNS를 쓰지 않는 고객(매장 공용 계정 등)을 위해 이메일·비밀번호로 가입합니다. 이메일 인증번호 확인 → 약관 동의 → 휴대폰 본인인증 순서이며, 비밀번호 재설정을 함께 제공합니다.
- MVP
사업자 회원 인증
국세청 API로 사업자등록번호 진위와 상태(계속·휴업·폐업)를 조회합니다. 인증되면 사업자가와 세금계산서 기능이 열립니다.
- MVP
휴대폰 본인인증
중복가입과 쿠폰 악용을 막고, 결제·환불 분쟁에 대비합니다.
- 2차
다매장·다배송지 관리
매장별 배송지·담당자·디자인 보관함을 따로 관리합니다.
- 2차
휴면 전환·복구
1년 동안 이용하지 않은 고객의 개인정보를 분리 보관하고, 로그인 후 본인인증을 하면 되살립니다.
- 검토 후보
기업(프랜차이즈) 계정
본사와 가맹점 계정을 연결하고, 본사 지정 품목·구매 승인 결재를 지원합니다. 2년 차 이후 검토할 후보라 기능 명세서에는 넣지 않았습니다.
#### 탐색·검색
- MVP
품목별 + 업종별 카테고리
‘카페 창업 필수품’, ‘배달 전문점 세트’처럼 업종 기준으로도 탐색합니다.
- MVP
한글 부분 일치 검색
자동완성(초성 포함), 동의어(수저집=수저포장지=수저봉투). 오타 보정과 형태소 검색은 2차 이후.
- MVP
B2B 필터
맞춤 인쇄 가능, MOQ, 소재, 친환경, 빠른 출고, 박스당 수량.
- 2차
기획전·창업 패키지
업종별 세트를 한 번에 담기.
- 2차
재구매 리마인드·추천
구매 주기를 계산해 “냅킨 떨어질 때가 됐어요” 같은 알림을 보냅니다. 같은 디자인을 다시 주문하는 맞춤 품목 리마인드는 2차, 일반 상품 리마인드와 상품 추천은 3차입니다(명세 U-SRCH-06).
#### 상품 상세
- MVP
수량 구간별 단가표
1박스 / 5박스 / 10박스 이상 같은 구간별 단가를 보여주고, 장바구니에서 자동 계산합니다.
- MVP
옵션·주문 단위·MOQ
사이즈·소재·색상 같은 옵션(최대 3단 조합), 함께 고르는 추가 구성품, 박스·롤·1,000매 같은 주문 단위, 최소 주문 수량. 인쇄 방식 같은 맞춤 인쇄 옵션은 맞춤 디자인에서 따로 고릅니다.
- MVP
맞춤 디자인 배지·제작 정보
인쇄 방식, 인쇄 영역, 제작 기간(영업일), 판비 안내.
- MVP
상세 설명
파트너가 쓴 이미지·글·표 상세 설명. 처음엔 일부만 보이고 [펼치기], 이미지 확대, 휴대폰용 크기로 빠르게 로딩. 주문할 때 본 버전을 주문 상세에서 다시 볼 수 있습니다.
- MVP
인증·시험성적서 열람
식품용 기구 적합 여부, 위생용품 신고 정보.
- 2차
샘플 신청
유료 또는 무료 샘플, 인쇄 샘플(교정쇄).
#### 장바구니·주문·결제
- MVP
파트너별 묶음 배송 장바구니
파트너·출고지·출고 유형(일반/맞춤)별로 묶고 배송비를 자동 계산합니다(무료배송 기준 금액 표시).
- MVP
결제 수단
카드, 간편결제(토스페이·카카오페이·네이버페이), 계좌이체, 가상계좌, 에스크로.
- MVP
증빙 발행
세금계산서 신청, 현금영수증, 카드 전표.
- 2차
대량 견적 요청(RFQ)
수량·사양을 입력하면 파트너가 견적을 내고, 고객이 수락하면 바로 주문됩니다.
- 3차
정기배송
빌링키 자동결제로 정해진 주기마다 주문합니다(명세 U-ORD-07).
- 검토 후보
B2B 후불결제
사업자 외상(월말 결제) 서비스를 제휴로 연동합니다. 2년 차 이후 검토할 후보라 기능 명세서에는 넣지 않았습니다(11장 더 붙일 수 있는 수익원).
#### 맞춤 디자인 핵심
- MVP
디자인 요청서
로고·참고 이미지 업로드, 매장명·문구, 색상, 스타일 키워드, 희망 납기.
- MVP
자체 인쇄 파일 주문
가진 AI·PDF 파일을 올리면 디자인팀이 무료로 인쇄 적합성을 검수합니다.
- MVP
디자인 협의 룸
실시간 대화, 시안 버전별 보기, 시안 위 핀 코멘트, 수정 요청과 확정 버튼.
- MVP
시안 확정(전자 동의)

## 맞춤 디자인 서비스 핵심
다른 커머스와 가장 크게 다른 부분입니다. 요청부터 재주문까지의 흐름, 상태, 소통 공간을 정의합니다. 기능 상세 명세 →
### 디자인 상품 유형
MVP
#### 템플릿형
준비된 템플릿에 매장명과 로고만 바꿉니다. 빠르고 무료이며, 디자인팀 부담이 가장 적습니다.
MVP
#### 맞춤형
전담 디자이너가 처음부터 만듭니다. 디자인비 39,000원, 같은 디자인의 맞춤 품목이 50만원 이상이면 무료입니다.
MVP
#### 자체 파일형
고객이 가진 AI·PDF 인쇄 파일을 올리면 디자인팀이 무료로 검수합니다. 고쳐야 하면 재업로드하거나 보정(10,000원)을 맡깁니다.
MVP
#### 재주문형
확정된 디자인을 그대로 씁니다. 디자인 단계와 판비가 없어 고객이 플랫폼에 계속 머물게 됩니다.
2차
#### 적용
확정된 디자인을 다른 품목(예: 수저집 → 컵·쇼핑백)에 맞게 다시 만듭니다. 디자인비 19,000원, 무료 수정 2회. 원 디자인 담당자에게 먼저 배정합니다.
2차
#### 브랜드 패키지
컵·홀더·쇼핑백·수저집 등 5품목까지 같은 톤으로 디자인하고 브랜드 컬러·로고 가이드를 줍니다. 정가 99,000원이며, 맞춤 주문에서는 품목별 합계(39,000원 + 추가 품목당 19,000원)보다 싸면 자동으로 적용합니다. 단독 상품으로도 팝니다.

고객디자인팀파트너시스템
고객

템플릿·맞춤·자체 파일 중 선택. 로고·문구·색상 입력 또는 인쇄 파일 업로드

C상품·품질·안전 정책식품용 기구·위생용품·친환경 표시
- 식품에 직접 닿는 제품(컵·용기·빨대·포장재 등): 식품용 기구·용기·포장 기준 및 규격에 맞는지 확인하고, 시험성적서와 ‘식품용’ 표시를 확인합니다. 식품위생법
- 위생용품(식당용 물티슈, 일회용 컵·수저·빨대·이쑤시개, 화장지, 종이냅킨 등): 위생용품 제조업·수입업 신고 여부와 표시 사항을 확인합니다. 위생용품 관리법
- 친환경 표시: ‘생분해’, ‘친환경’ 같은 문구는 환경표지 인증 등 근거가 있어야 합니다. 근거 없이 쓰면 그린워싱으로 제재받을 수 있습니다. 환경기술산업법
- 상품정보제공고시: 품목별 필수 정보(소재, 제조국, 제조자, 규격)를 입력해야 등록됩니다. 전자상거래법 고시
- 일회용품 규제 안내: 매장 안 일회용품 사용 규제는 자주 바뀌므로 해당 품목 상세에 최신 안내를 붙입니다. 본사가 카테고리마다 안내 문구를 쓰고 고치며, 그 카테고리 상품 상세에 접힌 안내 상자로 고친 날짜와 함께 보여 줍니다(문구가 없으면 상자 없음, 2026-10-15 확정, 명세 A-PRD-02·U-PDP-04). 자원재활용법
- 금지 품목: 인증이나 신고가 없는 식품 접촉 제품, 상표권 침해품, 위조품.
- 상세 설명: 연락처·외부 링크·QR, 다른 쇼핑몰 이름·로고·쿠폰, 가격·할인 문구(가격 영역과 달라질 수 있음)는 넣을 수 없습니다. 상품정보제공고시는 이미지로 대신할 수 없고 정해진 칸에 씁니다. 사진·글의 권리는 파트너가 보증합니다.
- 검수: 신규 상품은 운영팀 검수 후 노출하고, 상세 설명을 포함한 주요 정보를 바꾸면 다시 검수합니다. 입점 뒤 샘플 점검은 운영팀이 수작업으로 하고 상품 검수 기록에 ‘샘플 점검’ 메모로 남깁니다(2026-10-14 확정, 명세 A-PRD-01). 신고 기능을 둡니다.
D가격·주문·결제·증빙 정책구간 단가·MOQ·에스크로·세금계산서
- 가격 표시: VAT 포함 가격을 기본으로 보여주고, 사업자 회원에게는 공급가를 함께 표시합니다.
- 수량 구간 단가: 장바구니에 담긴 총수량으로 구간을 적용합니다. 옵션끼리 수량을 합산할지는 상품별로 설정합니다.
- 사업자 전용가(2026-10-13 확정): 파트너가 고르면 사업자 인증 회원에게만 보이는 사업자가를 둡니다. 할인율(모든 구간에 같은 비율, 상한은 관리자 설정값) 또는 구간별 숫자(모든 구간 필수) 중 상품마다 한 방식이고, 맞춤 단가에도 둘 수 있습니다(판비·교정쇄 제외). 디자인비 50만원 무료 판정은 실제로 적용된 가격 기준이라 사업자 회원은 같은 수량이라도 기준에 못 미칠 수 있으며, “○원 더 담으면 디자인비 무료” 안내로 추가 구매를 유도합니다.
- MOQ: 최소 주문 수량에 못 미치면 주문할 수 없습니다(맞춤 MOQ는 따로 둠).
- 에스크로(구매안전서비스): PG사 에스크로를 적용합니다. 전자상거래법
- 가상계좌: 입금 기한 3일, 기한 안에 입금되지 않으면 자동 취소.
- 판매자가 섞인 결제: 한 번의 결제에 파트너 상품과 본사 상품(디자인비·옵션·멤버십·PB)이 함께 들어가므로, PG 오픈마켓 계약에서 본사를 하위몰로 등록해 판매자별로 정산·증빙을 나눕니다. 부분 환불은 해당 판매자 몫에서 처리합니다(PG 계약 시 확인 필요).
- 세금계산서: 중개 구조에서는 상품 대금 세금계산서를 원칙적으로 판매자(파트너)가 구매자에게 발행합니다. 플랫폼은 파트너에게 수수료 세금계산서를 발행하고, 파트너 대신 발행해 주는 기능(위수탁 발행)을 제공합니다.
- 카드 결제 건: 카드 매출전표가 증빙이므로 세금계산서를 중복 발행하지 않습니다.
- 포인트: 무상 적립 포인트만 운영합니다. 돈을 충전해 쓰는 포인트는 선불전자지급수단이 되어 전자금융업 등록이 필요하므로 초기에는 도입하지 않습니다.
E배송 정책묶음배송·대량 화물·출고 기한
- 배송비: 파트너가 설정합니다(기본 배송비, 무료배송 기준 금액). 묶음 배송 단위는 ‘파트너 + 출고지 + 출고 유형(일반/맞춤)’입니다. 배송비와 무료배송 쿠폰이 모두 이 단위로 계산됩니다(명세 C-PRICE-03).
- 부피가 큰 대량 주문: 화물택배나 용달 옵션을 두고, 착불 또는 별도 배송비를 받습니다. 도서산간은 추가 배송비.
- 출고 기한: 일반 상품은 결제 후 영업일 2일 안, 맞춤 제작은 파트너가 [인쇄 가능]을 확인한 날(교정쇄는 고객이 승인한 날)부터 리드타임 안. 넘기면 페널티.
- 배송 완료 처리: 택배사 추적 API로 자동 처리하고, 7일 뒤 자동 구매 확정.
- 지정일 배송(2차): 매장 오픈일에 맞춘 도착일 지정.

- 파트너가 발주를 확인하기 전에는 바로 취소됩니다. 발주 확인 뒤 출고 전에는 취소를 요청하고 파트너가 승인합니다(1영업일 안에 처리하지 않으면 자동 승인).

- 사업자가 사업 목적으로 산 경우 소비자 보호 규정이 적용되는 범위가 다를 수 있으므로 약관에 분명히 적습니다(법률 검토 필요).

 | 폐기 | 보관 기간이 끝나면 폐기할 수 있습니다. 끝나기 30일 전에 시스템이 고객에게 “지금 재주문하면 판비 면제가 이어진다”고 알립니다
 | 계약 종료 | 보관 중인 판을 폐기하고 폐기 확인서를 냅니다. 회사가 요청하면 회사가 지정한 파트너에게 넘깁니다(비용은 협의)
 | 고객 고지 | 상품 상세와 주문서에 “판은 제작 파트너가 보관하며 고객에게 넘겨드리지 않습니다. 보관 기간 안에 식업에서 재주문하면 판비가 면제됩니다”를 표시합니다. 판비를 낸 고객이 판을 달라고 할 때 거절할 수 있는지가 자문의 핵심 질문입니다

고객 약관에 함께 넣을 것
- 디자인 서비스 약관: 판은 넘겨주지 않는다는 것, 보관 기간과 폐기 전 알림, 확정 디자인은 회사 저작권이고 고객은 이용권을 가진다는 것, 원본 AI 이용권의 범위.

배포가 서로 막지 않게 하는 규칙
- DB 변경은 하위 호환으로: 컬럼 추가 → 두 앱 배포 → 쓰지 않는 컬럼은 다음 배포에서 삭제. 한 번에 바꾸면 먼저 배포되지 않은 앱이 깨집니다.
- 마이그레이션(Flyway)은 한 곳에서: 앱 시작 때 돌리지 않고, 배포 파이프라인의 별도 단계에서 한 번만 실행합니다.
- core를 바꾸면 영향받는 앱을 함께 배포: CI가 바뀐 모듈을 보고 배포 대상을 고릅니다. web만 바뀌면 web만 배포합니다.
i
두 앱에 걸친 기능
- 디자인 협의 룸: 고객은 web, 디자이너는 admin에 접속합니다. 메시지는 Redis pub/sub로 두 앱 사이에 중계해 실시간으로 주고받습니다.
- 로그인·세션 분리: 관리자는 별도 도메인·쿠키·세션을 써서, 고객 쪽 취약점이 관리자 권한으로 번지지 않게 합니다.
- 앱 사이 호출 없음: web과 admin은 서로 API를 부르지 않고 같은 DB와 Redis만 봅니다.

파일 변환은 따로 가둡니다(convert)
- 이유: 미리보기를 만드는 Ghostscript·ImageMagick에서는 악성 PDF·PS 파일로 서버 명령을 실행하는 취약점이 해마다 나옵니다(2024년에도 -dSAFER 보호를 우회한 사례). 악성코드 검사는 알려진 악성 파일만 거르므로 이런 공격 파일을 막지 못합니다. batch에는 DB 쓰기 권한과 PG 지급대행 키가 있어서, 같은 곳에서 변환하면 파일 하나로 정산·지급까지 뚫릴 수 있습니다.
- 방식: batch가 변환할 파일마다 convert 작업을 띄웁니다(ECS RunTask). convert에는 DB 계정·Redis·PG 키를 주지 않고 S3 권한도 주지 않습니다. 대신 batch가 그 파일 하나를 읽는 주소와 결과(미리보기·썸네일·결과 JSON)를 쓰는 주소를 짧은 서명 주소로 넘기고, 작업이 끝나면 batch가 결과 JSON을 읽어 DB에 반영합니다.
- 설정: Ghostscript는 -dSAFER, ImageMagick은 policy.xml로 PS·EPS·PDF·XPS 처리와 외부 파일·URL 읽기를 막고, 작업마다 실행 시간·메모리 상한을 둡니다.
- 비용: 파일이 올라올 때만 몇 분 실행되므로 월 몇 달러 수준이고 ECS 비용에 포함됩니다.

### 1인 개발 원칙
- 범위를 먼저 동결합니다. MVP 기능은 기능 명세서의 MVP 목록으로 고정하고, 새 아이디어는 2차 목록에만 적습니다.
- 코드는 하나, 실행 앱은 셋. core를 공유하는 web·admin·batch를 따로 배포해 한쪽 배포가 다른 쪽을 막지 않게 합니다.
- 돈 계산은 테스트로 지킵니다. 가격·환불·정산 계산(C-PRICE, C-PAY, C-STL)의 예시 숫자를 그대로 단위 테스트로 만듭니다.

- 인프라는 코드로 남깁니다. Terraform과 README로 남겨 두면 나중에 사람을 뽑아도 바로 이어받을 수 있습니다.
- 만들지 말고 빌려 씁니다. 핵심(주문·디자인·정산)이 아닌 기능은 아래처럼 외부 서비스나 수작업으로 시작합니다.
