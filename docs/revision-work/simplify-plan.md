## 원인

매 세션 프로토타입 엔진·페이지 에이전트가 빈칸을 찾고, 빈칸 하나가 결정 하나가 됨. 영역을 줄여도 이 방식이면 다시 쌓이므로 **규칙 한 줄을 먼저** 넣는다.

## 1단계 — 범위만 줄임(동작은 그대로, 결정 거의 없음)

1. **작업 규칙 추가**(HANDOFF ‘작업 규칙’): “명세에 없는 세부(알림 채널, 상수 값, 드문 예외)는 개발 때 기본값으로 정하고 확인 거리로 올리지 않는다. 돈·법·고객 권리에 걸리는 것만 확인 거리로 올린다.” 페이지 에이전트 지시문(`page-agent-prompts.md`)과 `prototype-impact.md` 확인 거리 작성 기준에도 같은 문장.
2. **정책값 키 줄이기**(A-SYS-03, 163개): 운영자가 실제로 바꿀 값(수수료율·무료배송 기준·쿠폰·처리 기한·SLA·디자인비 등)만 관리자 설정 키로 남기고(목표 30개 안팎), 나머지는 ‘코드 상수(배포로 변경)’ 표로 옮김. 법정 값은 지금처럼 키 아님. 명세 본문의 `(정책값 키)` 표기는 남는 키만. 결과는 결정 하나로 기록(D74~).
3. **알림 줄이기**(C-NOTI-01, 코드 129개 × 채널 표): 기획 단계에서는 ‘필수 알림 목록(결제·배송·클레임 결과·법정 고지·보안) + 채널 원칙 몇 줄’만 두고, 코드별 채널 칸·묶음·재알림 시점은 개발 때 정함. 명세 본문의 알림 코드 언급은 그대로 둬도 됨(목록의 근거).
4. 1단계로 없어지는 S13 확인 거리: 2·5·6·8·10·11·12번(키·알림 세부). 남는 S13 결정 거리(3·4·16·17)는 3단계 6번과 겹치면 함께.
